# Разработка и эксплуатация

React + TipTap + Yjs на клиенте, Fastify + Hocuspocus + Kysely на сервере. Описание продукта — в [README](../README.md), архитектура и правила для агентов — в [AGENTS.md](../AGENTS.md), история изменений — в [changelog.md](changelog.md).

## Что работает

- Монорепозиторий npm workspaces, строгий TypeScript, ESLint, Prettier и Vitest.
- Первый запуск: выбор SQLite или существующей MariaDB, создание администратора, режим регистрации. Открытая регистрация, вход, access JWT на 15 минут, refresh cookie на 30 дней, выход и отзыв сессий. Пароли Argon2id, ограничение частоты входа, проверка Origin.
- Три панели: навигация, список с группировкой по датам, редактор или приветствие. На узком экране панели показываются по очереди.
- Записные книжки, цвет, подразделы, создание/переименование/удаление/сворачивание. При удалении книжки заметки остаются в «Все заметки».
- Метки, закрепление, локальный поиск MiniSearch, перенос в корзину и восстановление.
- TipTap: жирный, курсив, зачёркивание, спойлер по клику, ссылки, H2/H3, списки, чек-листы с датой, отмена/повтор. Автосохранение текста и заголовка.
- Задачи на главном экране и отдельная вкладка с группами. Отметка изменяет сам Yjs-документ заметки.
- Документы `space:<userId>` и `note:<noteId>`, локальное хранение в IndexedDB, синхронизация через `/collab`. Правки при недоступном сервере отправляются после восстановления соединения.
- Изображения: выбор файла, вставка из буфера, drag & drop, очередь в IndexedDB, загрузка до 20 МБ. Сервер поворачивает изображение, удаляет EXIF, создаёт WebP и превью; доступ проверяется по владельцу.
- Сервер сохраняет Yjs-состояния, производные `notes_index` / `tasks`, полные снапшоты `note_versions`. Снапшоты при активном редактировании не реже одного раза в 5 минут; закрытие заметки и ручная кнопка ставят версию в устойчивую локальную очередь до связи с сервером.
- Production PWA с локальными шрифтами и кэшем оболочки. Для первого офлайн-запуска нужно хотя бы раз открыть приложение с сетью.

## Локальный запуск

Нужен Node.js **22.12+** (рекомендуется 22 LTS) и npm. Команды npm выполняются из `app/`.

```bash
cd app
npm ci
npm run dev
```

Открыть **http://127.0.0.1:5173**. Vite проксирует `/api` и `/collab` на сервер **1339**. Мастер первого запуска создаст базу в `data/`. Папка не отслеживается Git. Для SQLite ничего дополнительно устанавливать не нужно, если для платформы доступна готовая сборка better-sqlite3; иначе понадобятся Python и инструменты C/C++.

Production-проверка, включая service worker:

```bash
npm run build
npm start
```

Открыть **http://127.0.0.1:1339**. Не запускайте одновременно dev-сервер и production-сервер на одном порту.

`npm start` из `app/` читает необязательный `../.env`; пример — корневой `.env.example`. При `npm run dev` задавайте настройки через переменные окружения. По умолчанию данные находятся в корневой `data/`, рядом с `app/`, независимо от рабочей папки процесса. `DATA_DIR` может указывать на отдельную тестовую папку. JWT-ключ генерируется в `data/jwt.key`, если `JWT_SECRET` не задан.

## Docker

Готовый образ собирает GitHub Actions: `ghcr.io/kozhevyatov/selfnote` (теги `latest`, `sha-…`, версии релизов).

```text
/volume2/docker/selfnote/
├── docker-compose.yml    из репозитория
├── .env                  настройки (пример — env.example)
└── data/                 постоянные данные
```

1. Положить `docker-compose.yml` и `env.example` (переименовать в `.env`) в папку сервиса, создать `data/`.
2. Права на `data/` настраивать не нужно: при старте контейнер сам передаёт папку пользователю сервиса (по умолчанию `node`, UID/GID 1000:1000) и только потом сбрасывает права root. Чтобы файлы принадлежали вашему пользователю DSM, задайте в `.env` `PUID` и `PGID` (узнать: `id` по SSH). У общих папок Synology есть ACL: если записать всё же нельзя, сервис стартует от root с предупреждением в журнале.
3. Существующая MariaDB в другой Docker-сети (на Synology — сеть `db`): раскомментировать блоки `networks` в compose. По умолчанию используется SQLite.
4. Запуск и обновление:

```bash
docker compose pull
docker compose up -d
docker compose logs -f selfnote
```

Сборка образа из исходников (`app/`): `docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build`.

5. В Nginx Proxy Manager направить домен на адрес NAS и порт **1339** (или `selfnote:1339`, если NPM в той же сети). Включить **Websockets Support**, выпустить HTTPS-сертификат.
6. Для HTTPS задать в `.env` `APP_ORIGIN=https://ваш-домен` и `COOKIE_SECURE=true`, затем `docker compose up -d`.
7. Пройти мастер в браузере. Для MariaDB база должна уже существовать, кодировка `utf8mb4`, у пользователя — права на таблицы, индексы и миграции.

`TRUST_PROXY` включайте только когда прямой доступ к сервису закрыт и запросы действительно приходят через доверенный прокси. Без него за NPM все пользователи выглядят для сервера одним IP, поэтому вход дополнительно ограничен по аккаунту (5 неудачных попыток → пауза 15 минут). Healthcheck: `/api/health`.

**Открывайте сервис по HTTPS-домену.** По `http://IP:1339` заметки создаются и синхронизируются, но браузер не включает service worker вне защищённого контекста — офлайн-запуск PWA и установка на телефон работают только через HTTPS (или `localhost`).

## Хранение и резервные копии

- `data/database.json` — выбранная БД и параметры подключения (права файла 0600). В случае MariaDB здесь есть пароль; защищайте резервные копии этой папки.
- `data/selfnote.sqlite`, `-wal`, `-shm` — SQLite. Для файловой копии остановите контейнер или используйте SQLite backup API; не копируйте только основной файл во время записи.
- `data/jwt.key` — ключ токенов.
- `data/attachments/<userId>/<sha256>.webp` и `.preview.webp` — изображения.
- Для MariaDB отдельно сохраняйте дамп существующей БД и папку `data/`.

Локальные документы и кэш изображений разделены по ID пользователя. Выход отзывает серверную сессию, но не удаляет локальные данные; на общем компьютере после выхода очистите данные сайта. Без ранее выполненного входа открыть приложение офлайн нельзя. IndexedDB не заменяет бэкап: браузер или пользователь может очистить хранилище.

## Проверки

Выполняются из папки `app/`.

```bash
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run build
```

Интеграционный тест поднимает сервер на `127.0.0.1:14339` с временной SQLite-базой и удаляет её после проверки. Проверяет настройку, логин/refresh/отзыв, WebSocket двух клиентов, офлайн-изменения, новую заметку до подключения, индексы задач и версии, запрет доступа другого пользователя, загрузку изображения и отсутствие EXIF, CSRF. Порт должен быть свободен.

Ручная приёмка:

1. Открыть production-сборку, пройти мастер и открыть вторую вкладку под тем же пользователем.
2. Создать заметку и чек-лист, задать сегодняшний срок. Проверить появление задачи на приветствии.
3. Отметить задачу на приветствии; открыть заметку в обеих вкладках и проверить галочку.
4. Отключить сеть в DevTools. Создать заметку, изменить чек-лист, вставить картинку. Перезагрузить страницу при активном service worker: данные должны остаться.
5. Включить сеть; дождаться статуса «Синхронизировано», проверить вторую вкладку и изображение.
6. Повторить настройку на чистой **тестовой** базе MariaDB и проверить перезапуск контейнера. Не подменять `database.json` существующей установки без резервной копии.

## Следующие этапы и ограничения

Это фундамент первого прохода, а не весь продукт из AGENTS.md. Пока не реализованы:

- шифрование заметок, публичные ссылки и OG-превью;
- приглашения, гости с PIN и совместная работа разных аккаунтов (один аккаунт в нескольких вкладках уже синхронизируется);
- отправка приглашений при режиме регистрации «по приглашению» — сейчас этот режим запрещает самостоятельную регистрацию;
- серверный полнотекстовый поиск;
- повторы, уведомления, нативное приложение.

При закрытии вкладки версия ставится в локальную очередь; её отправка гарантируется при следующем открытии приложения с сетью, а не за счёт ненадёжного запроса при выгрузке страницы. Просмотренные изображения доступны офлайн; ещё не загруженные на устройство изображения требуют сети. Все заметки аккаунта синхронизируются на устройство (это и есть полноценный офлайн) через одно общее WebSocket-соединение; текст и задачи каждой заметки пересчитываются только после её изменения. Для архивов в тысячи заметок позже понадобится подгрузка по требованию.

## Открытые вопросы

- Подтвердить свободный порт **1339** и домен на NAS.
- Проверить первый запуск на существующей MariaDB и реальную сборку Docker на NAS: в среде разработки Docker и экземпляр MariaDB отсутствовали; этот критерий пока не подтверждён.
- Шифровать ли заголовок защищённой заметки и какие лимиты назначать гостям — для следующих этапов.
- Токен 15 минут используется для открытия WebSocket; уже открытое соединение проверяет действительность refresh-сессии на каждом сообщении. Принудительный отзыв сессии запрещает дальнейшие сообщения.
