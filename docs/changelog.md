## 16 ноября 2026 — этап 3: история версий и корзина

16 ноября 2026. Выполнены только §8.6 и §8.1; остальные пункты раздела 8 не реализовывались.

**Что сделано:**

- Кнопка «История» открывает боковую панель с группировкой версий по дням, временем и именем автора. Есть ручное сохранение версии, просмотр форматированного содержимого только для чтения, картинки и отключённые элементы управления задачами.
- Переключатель «Показать изменения» сравнивает текст выбранной версии с текущим: добавленное зелёное, удалённое красное зачёркнутое. Сравнение построчное; для очень больших документов предусмотрен предел памяти. Изменения форматирования и атрибутов задач отдельно не подсвечиваются.
- API списка версий не передаёт `state`; API отдельной версии возвращает base64. Все запросы проверяют владельца и принадлежность версии заметке.
- Восстановление после подтверждения клонирует содержимое старого снапшота в живой Yjs-документ как новое изменение. Простое применение старого update не использовано: оно не возвращает удалённые узлы. Перед изменением сохраняется «До восстановления», после — «Восстановленная версия». Изменение приходит другим подключённым клиентам. В интерфейсе восстановление разрешается после синхронизации; история требует сети. Заголовок и размещение заметки, хранящиеся в документе пространства, не откатываются.
- В корзине доступны восстановление, окончательное удаление одной заметки и очистка всей корзины. Необратимые действия требуют подтверждения. Очистка всей корзины включает также заметки, скрытые текущим поисковым запросом.
- Клиент удаляет заметки с `deletedAt` старше 30 дней при загрузке локального пространства, синхронизации и периодической проверке. Тела окончательно удалённых заметок очищаются из IndexedDB, провайдеры отключаются, локальная очередь версий очищается.
- Сервер удаляет тела заметок, задачи, индексы и историю при синхронизации удаления, а также при запуске и раз в сутки. Проверяется именно дата удаления из пространства, а не дата последней правки. Серверная уборка обновляет живое пространство, поэтому удаление видят подключённые устройства.
- Синхронизируемая карта `purged` и серверная таблица `purged_notes` сохраняют отметки окончательного удаления: старое офлайн-устройство не может повторно создать тело удалённой заметки. Запись документов, создание версий и восстановление сериализованы, чтобы отложенная запись не возвращала очищенные данные.
- При фоновой уборке удаляются неиспользуемые серверные изображения и превью. Учитываются ссылки из текущих документов, живых документов и сохранённых версий. Загрузки моложе 30 дней сохраняются как запас времени для офлайн-очереди; поэтому свежий неиспользуемый файл может пережить удаление заметки.
- Изменения схемы находятся только в новой миграции `003_history_and_trash`: `notes_index.deleted_at` с заполнением из существующих пространств, `note_versions.label`, таблица `purged_notes`. Миграции `001` и `002` сохранены.
- Сохранены имеющиеся доработки от 15 ноября: Y.Map по полям, единое WebSocket-соединение, кэш извлечения, составные ключи задач и очередь версий. В рабочей папке отсутствует `.git`, поэтому подтвердить авторство конкретных изменений Claude по истории коммитов невозможно. Коммит и push не выполнялись.

**Что проверено:**

- Из `app/` успешно выполнены `npm run typecheck`, `npm run lint`, `npm test` (11 тестов), `npm run test:integration`, `npm run build`.
- Unit-тесты: восстановление удалённых узлов вместе с форматированием на другой реплике, граница 30 дней, оба формата метаданных, текстовый дифф и ограничение памяти.
- Интеграция на временной SQLite: получение истории и автора без передачи снапшотов в списке, запрет чужого доступа и подстановки версии другой заметки, восстановление на двух WebSocket-клиентах и обе записи истории.
- Интеграция корзины: исключение и возвращение задач, удаление через 31 день на другом устройстве, очистка серверных таблиц, ручное окончательное удаление, запрет повторного подключения старого документа и повторного создания метаданных.
- Перезапуск сервера без клиентов: очистка старой корзины и неиспользуемого файла; изображение, которое осталось только в истории живой заметки, сохранено.
- В браузере на production-сборке и отдельной временной базе: список версий, сохранение, форматированный просмотр с `contenteditable=false`, текстовый дифф, подтверждение восстановления и появление записей «До восстановления» / «Восстановленная версия». Обнаруженная при проверке ошибка чтения стандартного поля Yjs исправлена: предпросмотр использует `content`.

**Что не удалось проверить и почему:**

- MariaDB и сборка/запуск Docker на Synology не проверены: доступной тестовой MariaDB и среды NAS в этой сессии нет. Миграция написана через Kysely без SQL, специфичного для SQLite.
- Суточный таймер не ожидали в реальном времени: тот же обработчик проверен при перезапуске сервера на подготовленных старых данных.
- Первоначально sandbox запрещал тестовому серверу слушать локальный порт; интеграция успешно выполнена после разрешения локального запуска.
- При браузерной проверке старый service worker продолжал отдавать прежнюю сборку на первом тестовом origin. Исправленная сборка проверена на чистом origin `localhost`; механизм обновления PWA в рамках этих двух пунктов не менялся.

Миграция `003` применяется при запуске автоматически.

## 15 ноября 2026 — исправления после ревью

- Задачи на сервере хранятся с ключом «заметка + id» (миграция `002_task_keys_and_trash`, производные таблицы пересобираются из сохранённых документов). Раньше пункт чек-листа, скопированный в другую заметку, ломал сохранение второй заметки на сервере. Добавлен интеграционный тест.
- Клиент: одно WebSocket-соединение на все документы вместо отдельного на каждую заметку (у Chrome лимит ~255 соединений); кэш извлечённого текста/задач по заметке; поисковый индекс строится только во время поиска.
- `uuid()` с запасным вариантом на `crypto.getRandomValues` — создание заметок и книжек работает и по HTTP без HTTPS.
- Свойства заметки в документе пространства хранятся как `Y.Map` по полям: одновременные офлайн-правки разных полей (название на одном устройстве, книжка на другом) больше не затирают друг друга. Старые заметки переводятся в новый формат при первом изменении.
- Список заметок группируется как в макете: Закреплённые, Сегодня, Вчера, На этой неделе, затем месяцы; справа у группы — дата.
- Корзина: `notes_index.deleted` обновляется из документа пространства, `/api/tasks` не отдаёт задачи из удалённых заметок.
- Вход: лимит неудачных попыток по аккаунту (работает и за прокси).
- Прореживание `note_versions`.

Проверено: `typecheck`, ESLint, новые функции общего пакета. Unit-тесты Vitest, интеграционный тест и сборку нужно прогнать на Mac (`npm test`, `npm run test:integration`, `npm run build`).
