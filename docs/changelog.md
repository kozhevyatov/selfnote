## 23 ноября 2026 — мобильное приложение (этап 10, шаг 1): вход, синхронизация, списки

**Сервер:**
- Вход для приложений: с заголовком `X-SelfNote-Client: app` ответы `/api/auth/login`, `/api/auth/register` и `/api/setup` содержат `refreshToken` в теле (cookie не ставится), а `/api/auth/refresh` и `/api/auth/logout` принимают его в теле запроса. Без заголовка всё работает как раньше: токен из тела браузеру не поможет. Интеграционный тест на это добавлен. **Нужна пересборка образа.**

**Приложение `mobile/`** (Expo + React Native, вне npm workspaces — образ Docker и CI не затронуты):
- Экран входа: адрес сервера (можно без `https://`), почта, пароль. Перед входом проверяется, что по адресу SelfNote и он настроен. Refresh-токен — в Keychain/Keystore, access-токен — в памяти, обновляется заранее.
- Синхронизация в том же формате Yjs, что у веба: одно WebSocket-соединение на все документы, офлайн-копия каждого документа в SQLite. Без сети открывается последняя копия, правки догоняют сервер.
- Главный экран по макету: дата, поиск, книжки и подразделы чипами, «Сегодня в задачах» (отметка прямо с главной), закреплённые, группы «Сегодня / Вчера / На этой неделе / месяцы». Точка у аватара — состояние связи.
- Вкладки «Задачи» (просрочено, сегодня, предстоящие, без срока, выполненные), «Книжки» (с подразделами, открывают отфильтрованный список), «Настройки» (аккаунт, сервер, выход).
- Заметка открывается для чтения (заголовки, списки, ссылки, скрытый текст по нажатию), задачи отмечаются. Тема и акцент берутся из настроек пространства, как в вебе.
- Пока нет: редактора и создания заметок (следующий шаг — 10tap), картинок, заметок под паролем.
- Общий код берётся из `app/packages/shared/src` через `metro.config.js`. Зависимости ставятся по `mobile/README.md`; `typecheck` приложения — на Mac после установки.

## 21 ноября 2026 — гости по ссылке + PIN (этап 6), блокировка и удаление пользователей (этап 8)

**Гостевой доступ (этап 6 завершён):**
- В окне «Совместный доступ» новый блок «Гостевые ссылки»: персональная ссылка `/g/<токен>` и PIN (от 6 символов, по умолчанию случайные 6 цифр). Настраиваются роль (редактор/читатель), срок (1, 7, 30 дней или бессрочно), лимит устройств (1, 2, 3, 5 или без ограничения) и пометка «для кого». PIN показывается один раз и хранится только хешем argon2id.
- Гость открывает ссылку, вводит имя и PIN — аккаунт не нужен. До ввода PIN видно только, кто пригласил и с какими правами; название заметки не раскрывается. Имя гостя видно в «Сейчас в заметке» и в истории версий («Имя (гость)»).
- 5 неверных PIN подряд блокируют ссылку на час (счётчик в базе, переживает перезапуск). Владелец видит блокировку и может снять её раньше. Дополнительно — лимит запросов по IP.
- Владелец меняет роль ссылки, видит вошедшие устройства, сбрасывает их и отзывает ссылку — гости отключаются сразу. Отозванная ссылка остаётся в базе с `revoked_at`, чтобы имена гостей в истории не пропали.
- Устройство гостя: httpOnly-cookie только для пути этой ссылки (30 дней) + JWT на 15 минут с `gsid` для WebSocket и картинок. Токен гостя не открывает API пользователей, пространство владельца и другие заметки. Права перепроверяются при подключении и раз в 5 секунд.
- Гости не могут загружать картинки (вставка и перетаскивание файлов отклоняются), существующие картинки заметки видят через `/api/guest/<токен>/img/<id>`.
- Гостевая ссылка перестаёт работать, если заметку убрали в корзину, закрыли паролем, удалили или заблокировали владельца. Заметку с действующими гостевыми ссылками нельзя закрыть паролем.
- Гостевая страница работает без локальной копии — нужна сеть.

**Админка (этап 8 завершён):**
- Настройки → Пользователи: «Заблокировать / Разблокировать». Блокировка завершает все сессии и WebSocket-соединения пользователя, вход отвечает «Аккаунт заблокирован администратором» (только после верного пароля). Данные сохраняются; его общие заметки, гостевые и публичные ссылки не открываются другим до разблокировки.
- «Удалить» с подтверждением вводом почты пользователя: удаляются аккаунт, заметки (с надгробиями в `purged_notes`, чтобы устройства участников их не вернули), история, задачи, картинки (и файлы), публичные и гостевые ссылки, доступы, приглашения, хранилище паролей. Правки пользователя в чужих заметках остаются в их истории без имени.
- Кнопки действий в строке пользователя — иконки с подсказками: ключ (новый пароль), запрет/открытый замок (блокировка), корзина (удаление). Имя и почта больше не перекрываются.
- Нельзя заблокировать или удалить себя и последнего действующего администратора; снятие роли тоже учитывает только незаблокированных администраторов.

**Технически:** миграции `009_guest_links` (таблицы `guest_links`, `guest_sessions`) и `010_user_blocking` (`users.blocked_at`). Редактор: панель форматирования и окно ссылки вынесены в общие компоненты, добавлен `GuestEditor`. Интеграционный тест дополнен сценариями гостей и админки.

Проверки: `typecheck` и `lint` проходят. `npm test` и `npm run test:integration` в среде агента не запускались (нативные модули собраны под macOS) — их нужно прогнать на Mac. Нужна пересборка Docker-образа.

## 18 ноября 2026 — заметки «Пароли», перо и отступы корзины

- Выбор типа при создании через стрелку у «Новая заметка»: обычная заметка, список задач, пароли. В навигации появился раздел «Пароли» под «Задачами»; в списке записей — значок ключа.
- У заметки «Пароли» зашифрованное название и несколько блоков: название записи, адрес, логин, пароль. Добавление, перемещение, дублирование, удаление с подтверждением; показ одного пароля, копирование, генератор на WebCrypto (24 символа).
- Общий мастер-пароль: шифрует случайный 256-битный ключ хранилища, который существует открытым только в памяти. Конверт ключа хранится на сервере в персональной записи `settings` и локально в зашифрованном виде. Первая настройка требует сети, последующее открытие и создание доступны офлайн после загрузки данных. Используется существующий AES-GCM и PBKDF2-SHA-256 (600 000 итераций).
- Новая запись сразу создаётся зашифрованной, без открытого Y.Doc в IndexedDB. Автоблокировка через 5 минут бездействия, при скрытии страницы и вручную. Упорядочена локальная запись зашифрованных снапшотов, чтобы старое шифрование не перезаписывало новые правки.
- История хранится внутри шифра: последние 50 разных снимков, каждые 5 минут, при закрытии/блокировке, перед изменением пароля и удалением, вручную. Восстановление предварительно сохраняет текущее содержимое. Конфликт синхронизации сохраняет локальную версию отдельной зашифрованной копией.
- Публичные ссылки и снятие шифрования запрещены; совместный доступ недоступен. Пароли не попадают в текстовый поисковый индекс или задачи. Поиск разблокированных названий остаётся локальным. Обычные экспорты пропускают секреты с предупреждением; полный серверный бэкап включает шифр и конверт ключа.
- Ограничения первой версии: нет смены/восстановления мастер-пароля, TOTP и вложений. Книжки и метки — открытые метаданные. Очистка буфера через 30 секунд выполняется только при доступном API, активном окне и совпадении содержимого; гарантировать её в браузере нельзя.
- Логотип заменён на перо в интерфейсе, на экране входа, в favicon и PNG-иконках PWA. Кнопка «Очистить корзину» получила боковые отступы 16 px.
- Переключатель скрытия заголовка в модальном окне выровнен слева от подписи: исправлен унаследованный `flex-direction: column`. При недоступном WebCrypto теперь выводится сообщение о необходимости HTTPS вместо ошибки `importKey`.
- По просьбе владельца тесты, линтер, проверка типов и сборка не запускались. Команды и ручные сценарии: `docs/passwords-checklist.md`.

## 17 ноября 2026 — оптимизация совместного доступа

- WebSocket: права на документ перепроверяются не на каждое сообщение, а не чаще раза в 5 секунд на соединение. Смена роли, отзыв, корзина, пароль и удаление по-прежнему сразу закрывают соединение участника.
- Картинки в совместных заметках: новая миграция `007_note_attachments` — индекс «заметка → вложения» (текущее содержимое и история). Доступ участника к картинке проверяется одним запросом вместо перебора всех заметок и версий. Индекс заполняется при сохранении заметки и пересобирается при миграции и восстановлении из резервной копии.
- `onChange` пространства не обращается к базе для заметок, которые сейчас никто не открыл.

## 17 ноября 2026 — совместные заметки между пользователями

- Убрана временная диагностика интеграционного теста. Тестовый WebSocket-клиент блокирует отложенные переподключения после уничтожения; повторный прогон по просьбе владельца не запускался.

- Кнопка «Совместный доступ» в шапке обычной заметки: владелец приглашает существующий аккаунт по email и выбирает роль «Редактор» или «Читатель». Приглашение приходит внутри SelfNote, в раздел «Общие»; его можно принять или отклонить. Письма не отправляются.
- Редакторы одновременно меняют текст, заголовок и задачи через Yjs; офлайн-правки объединяются при подключении. Видно, кто сейчас открыл заметку. Читатель может смотреть заметку и историю, но не менять содержимое, задачи или версии.
- Владелец меняет роли и отзывает доступ; участник может покинуть заметку. Сервер проверяет права в REST и WebSocket, при изменении доступа переподключает участника. Чужое пространство (книжки, другие заметки) не раскрывается. Участники не могут удалять чужую заметку, шифровать её или создавать публичные ссылки.
- Общие заметки участвуют в локальном и серверном поиске и списке задач. Картинки редактора хранятся у владельца заметки; чтение вложений проверяется по доступной заметке и её истории. Корзина временно закрывает доступ участникам, восстановление возвращает его, окончательное удаление очищает приглашения.
- Новая миграция `006_note_members`; прежние миграции не менялись. Общие заголовок и дата находятся в документе заметки, личная организация остаётся в пространстве владельца. Список приглашений и прав обновляется каждые 10 секунд; открытая заметка синхронизируется в реальном времени. Локальная копия доступна офлайн; известный клиенту отзыв очищает документ с устройства, но не может удалить ранее сохранённые пользователем копии.
- Заметку с участниками или ожидающими приглашениями нельзя закрыть паролем: сначала нужно отозвать доступ. Гости по PIN, приглашения на регистрацию и курсоры внутри текста пока не входят в этот этап.
- При проверке интерфейса исправлены пустые POST/DELETE-запросы API (заголовок JSON теперь добавляется только при наличии тела) и изменение даты от служебного переключения редактора в режим чтения.

- Клиент: одно WebSocket-соединение на все документы вместо отдельного на каждую заметку (у Chrome лимит ~255 соединений); кэш извлечённого текста/задач по заметке; поисковый индекс строится только во время поиска.
- `uuid()` с запасным вариантом на `crypto.getRandomValues` — создание заметок и книжек работает и по HTTP без HTTPS.
- Свойства заметки в документе пространства хранятся как `Y.Map` по полям: одновременные офлайн-правки разных полей (название на одном устройстве, книжка на другом) больше не затирают друг друга. Старые заметки переводятся в новый формат при первом изменении.
- Список заметок группируется как в макете: Закреплённые, Сегодня, Вчера, На этой неделе, затем месяцы; справа у группы — дата.
- Корзина: `notes_index.deleted` обновляется из документа пространства, `/api/tasks` не отдаёт задачи из удалённых заметок.
- Вход: лимит неудачных попыток по аккаунту (работает и за прокси).
- Прореживание `note_versions`.

Проверено: `typecheck`, ESLint, новые функции общего пакета. Unit-тесты Vitest, интеграционный тест и сборку нужно прогнать на Mac (`npm test`, `npm run test:integration`, `npm run build`).
